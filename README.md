# 推特下载器（安卓版）

**Twitter / X 视频图片下载器（Android）— Twitter (X) Media Downloader for Android**

复制一条推文链接进来，就能下载里面的图片和视频：图片是原图，视频是最高画质。
在软件里登录自己的 X 账号后，需要登录才能看的内容（敏感内容等）也能解析下载。

Download photos and videos from Twitter / X tweets on Android — original-quality images and highest-bitrate videos, with in-app login for sensitive / login-required content.

## 下载安装

到本仓库的 **Releases** 里下载最新的 `推特下载器-vX.Y.Z.apk`，在手机上打开安装即可。
支持安卓 9 到安卓 16。第一次打开会申请通知权限（用来显示下载进度，可拒绝，不影响下载）。

## 主要功能

- 粘贴推文链接或从 X 分享到本软件，自动解析
- 图片下原图、视频下最高画质，一条推文里的多个媒体可单个下、也可全部下
- 预览带缩略图，视频能直接点开播、图片能点开看大图
- 后台下载：切到别的软件或锁屏也不会断，通知栏有进度
- 按作者分文件夹保存到 Download/推特下载/
- 深色模式适配

---

- 包名：`com.muse.xdownloader`，版本 1.0.8（versionCode 9）
- 支持系统：安卓 9（minSdk 28）到安卓 16（targetSdk 36）
- 纯 Java、无第三方库，只用安卓自带的 org.json

## 功能（v1.0.8）

1. **登录**：点主界面左上角「设置」进入设置页，在里面打开 X 官方登录页（WebView）自己登录；
   登录完成后读取 cookie 里的 `auth_token` + `ct0` 存在应用私有存储里。
   软件不接触、不保存密码，登录状态只留在手机系统 CookieManager 里。
   主界面只显示一行登录状态小字；退出登录也在设置页里（清 cookie + 清凭证），主界面不再摆登录/退出按钮，避免误点。
   **v1.0.2 起，设置页点「退出登录」会先弹确认框**（标题「确定要退出登录吗？」，说明退出后下载需要登录才能看的推文时得重新登录），
   点了确认才真的清 cookie + 凭证，点取消不退出。
   **v1.0.5 登录页 WebView 加固**（修“登录网页加载不出来”）：UA 换成真实 Chrome 安卓浏览器的（去掉 wv 标记）；
   补齐多窗口、JS 自动开窗、混合内容兼容等设置；装了 WebChromeClient——顶部有加载进度条、
   `window.open` 的验证窗口用全屏子 WebView 接住显示（关窗自动移除），JS 弹窗直接放行不卡页；
   主框架加载出错不再静默白屏，页面上方会弹出错误面板（大白话原因 + 系统错误原文和错误码 + 重试按钮）；
   页面加载完检测到已有 `auth_token` 会 Toast 提醒可以收尾；底部多了「页面打不开？换个入口重试」，
   在 `x.com/i/flow/login`、`x.com/login`、`twitter.com/i/flow/login` 三个官方入口间轮换。
   **v1.0.6 登录入口按状态显示**（用户在 v1.0.5 截图里指出已登录时设置页还同时摆着登录和退出两个按钮）：
   登录状态判断全应用只用一个口径——`MainActivity.isLoggedIn()` 静态方法，读凭证（LoginActivity.PREFS）里
   `auth_token` 存在且非空就是已登录，主界面和设置页都调它，不再各写一套。
   未登录时：主页在登录状态行下方、推文链接区上方直接摆一块登录区（一个醒目的「登录推特账号」按钮，
   点它和设置页里那个按钮一样打开 LoginActivity；v1.0.7 起删掉了按钮上方标题下面那句说明，
   v1.0.8 起连「还没登录推特账号」标题也删掉了，这块只剩按钮，见文末记录），
   第一次进来不用先去设置里找；登录成功后这块在主页隐藏（refreshLoginStatus 在 onResume 时刷新），
   主页只剩一行登录状态小字，登录入口回归设置页。
   设置页同样按状态只摆该有的按钮：未登录时只显示「登录推特账号」（没有「退出登录」），
   已登录时只显示「退出登录」（没有「登录推特账号」）；onCreate、onResume 和退出登录成功后都会立即刷新，
   退出完当场就变回未登录的样子。退出登录的确认弹窗不变。
2. **输入链接**：手动粘贴、从剪贴板粘贴；也支持系统分享（ACTION_SEND）和打开 x.com / twitter.com 的 `/status/` 链接自动填入。链接提取用正则，兼容 x.com、twitter.com、mobile.twitter.com 以及混着文字的分享文本。
3. **解析（v1.0.2 两段式：快速通道优先，WebView 兜底）**：
   - **第一段·快速通道（v1.0.2 新增，为了解决“解析很慢”）**：先直接发一个轻量请求
     `GET https://api.fxtwitter.com/status/{推文ID}`（连接/读取超时各约 8 秒，UA 用常见安卓 Chrome），
     解析返回 JSON 里的作者、正文、时间和 `tweet.media.all`（图片转原图，条目带 formats/variants 时选码率/分辨率最高的一档，
     视频的 `thumbnail_url` 存为预览图）。只要拿到至少 1 个媒体就直接进预览，不再开 WebView，公开推文一般几秒内完成。
     这条通道只能下公开推文、且第三方接口稳定性不由我们控制，所以它只是“加速器”，不是地基。
   - **第二段·WebView 兜底（v1.0.1 路线，逻辑不变）**：快速通道失败（超时、404、非 JSON、媒体为 0）时自动转入。
     界面状态行会先显示「正在快速解析…」，转兜底时改显示「快速解析没拿到，改用登录页面解析（稍慢）…」。
   - WebView 兜底解析时用同一个已登录 WebView 打开推文链接，让 X 自己的网页把内容加载出来，软件不写死任何接口参数。
   - a. JS 注入收集：页面加载后轮询执行 JS，收集 `<video>` 的 src/source、`<img>` 里的 `pbs.twimg.com/media` 图片，
     并从页面 HTML 片段里用正则提 `video.twimg.com` 的 mp4 直链和图片地址（含内嵌 variants 数组时按 bitrate 选最大的一档）。
     图片统一转原图（`?format=<原格式>&name=orig`）。
   - b. 拦截页面自己的 GraphQL 请求：WebViewClient 拦截到 URL 含 `/i/api/graphql/` 且是 TweetDetail / TweetResultByRestId 的请求时，
     用 CookieManager 的 cookie 和页面请求原来的请求头、按页面当时用的地址（queryId 从页面 URL 里现取，代码里不写死）再取一份响应体，
     递归遍历 JSON 解析媒体（图片收 `media_url_https`、视频在 `video_info.variants` 里选 video/mp4 码率最大者），顺带提作者、正文、日期。
     这份结果和 a 的结果合并去重。
   - c. 速度：轮询一收集到媒体且结果稳定（连续两次一样），或拦截到的 GraphQL 已给出媒体，就立即结束，
     不等满 30 秒上限；30 秒只是兜底时限，常见情况几秒内完成。
   - d. 视频只有 blob 流地址、又找不到 mp4 直链时，明确提示“这条视频只有流地址，第一版下不了”，不写假文件；
     如果同一条里还有图片，图片照常可下并给出提醒。
   - 仍然绝不写死 GraphQL queryId；仍然不接 vxtwitter / syndication 等其它公开解析。
     快速通道的 FxTwitter 只恢复为“第一段加速”，失败一律由 WebView 兜底接住。
   - 解析失败时用中文说清可能原因（链接不对、推文被删、没登录/登录过期、X 页面改版），不露堆栈。
4. **预览（v1.0.2 改成带预览图的列表）**：先显示作者、@账号、正文（截断约 200 字）和媒体总数，
   下面每个媒体一行：左边约 84dp 预览图（视频是封面图、图片是小图；后台异步加载、带 Cookie、内存缓存，
   加载中或失败时显示灰色占位并写「视频」/「图片」），中间是「第 N 个 · 视频/图片」和能拿到时的分辨率，
   右边是单独的「下载」按钮。各解析来源都尽量给每个媒体填预览图地址（快速通道用 thumbnail_url / 图片地址改 name=thumb；
   GraphQL 用 media_url_https；DOM 用 `<video>` 的 poster 和 `<img>` 地址改小图参数），拿不到就留占位。
5. **下载（v1.0.3 改为前台服务下载：真后台 + 通知栏 + 界面进度条）**：可以点某一行单独下载那一个，
   也可以点底部「下载全部媒体」一起下；两种方式走完全同一套保存逻辑和命名规则，文件序号按媒体在列表里的位置定。
   - v1.0.3 起，下载不在界面里自己开线程，而是打包成任务（推文信息 + 要下的序号 + 当前 Cookie，JSON 传递）
     交给新增的 `DownloadService`（前台服务，`foregroundServiceType="dataSync"`）在它自己的工作线程里依次下载，
     保存逻辑仍是原来 `Downloader` 的那套。界面在启动服务前先做完安卓 9 的存储权限检查。
     这样点完下载就可以切到别的软件、锁屏，下载不会被系统掐断；任务全部下完服务自己停掉，不长驻。
   - **队列**：下载进行中再点新的下载，新任务排到现有队列后面依次执行，不并发、不打断正在下的；
     单个文件失败会跳过继续下一个，最后汇总成功/失败个数。
   - **通知栏**：通知渠道「下载进度」。下载中有一条常驻通知：标题「推特下载器」，
     内容「正在下载 第N个/共M个 · 文件名」，知道总大小时带字节百分比进度条，不知道时用不确定进度；
     点通知回到主界面。全部下完换一条「下载完成 · 共N个文件」通知（有失败时写明「N个成功，M个失败」），可滑动清除。
   - **界面进度条**：预览区下方新增一条横向 ProgressBar（平时隐藏）。服务通过只发给本应用的广播
     （自定义 action，extras 带当前序号/总数/百分比/文件名/完成汇总）实时同步：界面显示当前文件百分比和
     「正在下载第N个/共M个 · xx%」，每行按钮的「下载中…/已下载」也跟着广播更新；下完进度条满格，完成文字保留。
     响应没有 Content-Length 时进度条自动变不确定模式，不会卡在 0。
   - **权限申请时机（v1.0.4 改）**：权限改成刚进软件就申请，不再等第一次下载才问。
     MainActivity.onCreate 界面建好后统一检查：安卓 13+ 没给通知权限的申请 POST_NOTIFICATIONS，
     安卓 9 没给存储权限的申请 WRITE_EXTERNAL_STORAGE，两个都缺就一次申请完；
     原“第一次下载时问一次”的逻辑已删除，不会重复弹。拒绝了也能正常下载
     （没通知权限只是通知栏里看不到进度，界面里的进度条照常；安卓 9 没存储权限时下载会失败并给中文提示），
     已被永久拒绝时系统会直接回调拒绝，软件不自制弹窗反复打扰、不会崩。
     下载前原有的安卓 9 存储权限检查（ensureStoragePermission）保留。
   - 下载请求头带登录 Cookie。存到 `Download/推特下载/<作者账号>/`；安卓 10+ 用 MediaStore.Downloads + RELATIVE_PATH，
     安卓 9 用传统目录 + 运行时申请存储权限（WRITE_EXTERNAL_STORAGE，maxSdkVersion 28）。
     文件名沿用 dy下载器的习惯：`<日期yyyyMMdd>-<作者账号>-<文案前约20字，非法字符替换>-<序号>.<扩展名>`，
     文案为空时用推文 ID 代替；图片 jpg/png、视频 mp4、动图按视频下。
6. **视频播放预览（v1.0.3 新增，v1.0.4 修比例）**：预览列表里视频（含动图）行多了播放入口——点预览图，
   或点行内的「▶ 播放」小按钮，打开 `PlayerActivity` 在线播放：VideoView + 系统 MediaController
   （可拖进度、暂停），打开后自动播放，带加载中提示。播的是解析到的 mp4 直链（和下载同一个地址），
   请求时用 `setVideoURI(Uri, Map)` 带上登录 Cookie 和 UA。播不了时提示「这个视频暂时播放不了，
   你可以直接下载后看」，不弹系统错误框。
   - **v1.0.4 修拉伸 bug**：以前布局里 VideoView 双向 match_parent，被硬撑满整个播放区域，
     16:9 的视频会被拉伸变形。现在布局只给 wrap_content 并居中；onPrepared 里取视频真实宽高，
     以可用宽（播放页宽）为基准按比例算高，超过可用高（根布局高 − 顶部栏高）时改以高为基准反算宽，
     把算出的尺寸 setLayoutParams 给 VideoView，之后再给 MediaController 重设锚点保证控制条位置对。
     视频宽高取不到（0）时退回 16:9 默认比例，不崩。
7. **图片全屏预览（v1.0.4 新增）**：预览列表里图片行点缩略图（行内文字有「点图片查看大图」提示），
   打开新增的 `ImagePreviewActivity`：黑底、全屏 ImageView，scaleType=FIT_CENTER 保持原图比例、绝不拉伸，
   顶部有返回和「@作者 · 第N张图片」。看的是下载用的原图（orig）地址，后台线程带 Cookie 加载，
   先下载字节、按屏幕最大边算 inSampleSize 再解码，避免大图爆内存；加载中转圈，失败 Toast「图片加载不了」。
   不做捏合缩放。视频行保持点开播放不变。

## 界面

- 颜色全部显式写死并做深色适配：`res/values/colors.xml`（浅色）和 `res/values-night/colors.xml`（深色）两套，
  跟随系统切换；背景、标题/正文、输入框文字与提示、按钮颜色都明确设置，两种模式下输入框文字都清楚可见。
  输入框有自己的底色和边框（`drawable/input_bg.xml`），不再是只有一条下划线。
- 主界面顶部有留白（内容 paddingTop 44dp），整体间距放宽松。
- 顶部左上角是「⚙ 设置」入口；设置页（SettingsActivity）放登录状态、登录/退出（v1.0.6 起按状态只显示该有的一个）和返回。
  未登录时主页自己也有一块登录区（见上），已登录时它自动隐藏。

## 构建

不用 Gradle，走手工流水线（aapt2 → javac → d8 → zipalign → apksigner），
工具在 `~/tools/sdk` 和 `~/tools/jdk17`：

```bash
bash build-apk.sh
```

产物：项目根目录的 `推特下载器-v1.0.8.apk`（用 `xdownloader.keystore` 签名；
后续版本升级必须继续用同一个 keystore 签名）。

注意：构建前需自备签名 keystore（见 `.gitignore`：`*.keystore` 和 `local.properties`
都被忽略），本仓库不含任何签名密钥和密码。第一次构建先按 `build-apk.sh` 里签名
步骤的提示用 keytool 生成自己的 `xdownloader.keystore`，再把密码通过环境变量
`KEYSTORE_PASSWORD` 或脚本同目录 `local.properties` 里的 `keystore.password=` 提供给脚本。

## 说明（还没法在这里验证的部分）

- 本机没有用户的 X 账号，真实登录、解析命中率和真机下载要用户在自己手机上实测：
  先试一条公开推文、再试一条登录才能看的推文，以他的实测为准。
- X 会不定期改版网页结构；新路线把 queryId、transaction-id 等都交给 X 自己的页面处理，
  理论上比写死接口耐用，但页面 DOM 改版时 JS 收集规则仍可能需要跟着调整。
- v1.0 的用户实测结论：登录和下载本身没问题（成功下到一条 @wifeqiandai 的视频推文），
  v1.0.1 修的是解析路线、解析速度、深色模式下输入框文字看不见、布局太靠上、登录/退出改到设置页这几件事。
- v1.0.1 的用户实测结论：解析还是慢；v1.0.2 加了快速通道（公开推文几秒内出结果，
  拿不到再走登录页面兜底）、带预览图的列表加逐个单独下载、退出登录确认框。
  快速通道在他手机网络下的实际耗时、预览图显示效果、单独下载仍需他真机实测确认。
- v1.0.2 之后用户确认要补的三样：下载进度条、视频播放预览、通知栏（真后台下载）。
  v1.0.3 已实现（前台 DownloadService + 通知进度 + 广播驱动的界面进度条 + PlayerActivity 在线播放），
  本机已构建验签通过；仍需他真机实测：点下载后切到别的软件/锁屏，下载是否继续、
  通知栏进度是否正常刷新、完成通知是否出现、视频点开能否在线播放、切后台回来后行按钮状态是否对得上。
- v1.0.3 用户实测结论：“这版没什么问题了”，只提了三个优化，v1.0.4 已实现：
  权限改到刚进软件就申请、图片也加了全屏预览、修了 16:9 视频在播放器里被拉伸变形的 bug。
  本机已构建验签通过（versionCode 5，证书与旧版一致）；仍需他真机实测：
  进软件是否立刻弹权限提示、图片点开能否全屏看大图、再拿一个 16:9 视频和一个竖屏视频各播一次看比例对不对。
- v1.0.4 用户实测反馈：登录网页加载不出来。后来确认他的测试习惯是每个版本都登出/重装后
  从零重新登录，所以当天上午 v1.0.1、v1.0.2、v1.0.3 他都是全新登录且能登，到 v1.0.4 才打不开。
  排查结论：顺手核查了 v1.0.4 的改动面——Manifest 里 LoginActivity 声明正常、没有
  `hardwareAccelerated=false`，主题还是系统 `Theme.Material.NoActionBar`，颜色资源和旧版
  activity_login 布局都是普通写法，`askStartupPermissions` 只申请通知/存储权限、与 WebView 无关，
  全项目也没有在启动时清 cookie 的代码（清 cookie 只发生在设置页点退出登录时）。
